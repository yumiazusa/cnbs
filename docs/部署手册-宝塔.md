# 国家统计局数据 MCP · 宝塔面板部署手册

> 环境：Ubuntu + 宝塔面板 + 无 Docker
> 服务：mcp-cnbs（国家统计局数据 MCP，MIT 协议，无需 API Key）
> 用途：为《数字经济案例与分析》实训提供权威宏观数据源，供 41 名学生并发查询

---

## 零、先想清楚一件事

自建这套服务，学生端**不会**经历"配置 MCP 服务器"的完整过程，只会经历"添加一个远程 MCP 连接"——填一个 URL、填一个令牌、点连接。大约 1 分钟。

这是**课堂应该做的分工**，不是妥协。MCP 真正的难点不在客户端（客户端只是填地址），而在服务端"怎么把数据变成 AI 能调用的工具"。你建好服务端，学生才有时间理解工具列表、参数结构、返回格式。

想让学生完整体验"从零起一个 MCP"，放在课后作加分项（见第六节），不要塞进 90 分钟。

## 一、前置条件

| 项目 | 要求 |
|---|---|
| 系统 | Ubuntu 20.04 / 22.04 / 24.04 |
| 宝塔版本 | 7.x 以上（需有「Node.js 版本管理器」） |
| Web 服务器 | **Apache 或 Nginx 都行，但配置完全不同**，先确认再用第五节的对应方案 |
| Node.js | ≥ 18（实机为 v20.18.3，路径 `/www/server/nodejs/v20.18.3/bin/node`） |
| 服务器 | 1 核 1G 起，20G 硬盘 |
| 出网 | 能访问 `data.stats.gov.cn`、`registry.npmjs.org` |
| 域名 | **必须有域名**。无备案域名也能用，但证书要走 DNS 验证，见第五节 |
| 端口 | 80（证书验证用）、443（对外服务） |

**启动前先验证出网，这一步不过后面全白搭：**

```bash
curl -s -o /dev/null -w "%{http_code}\n" "https://data.stats.gov.cn/easyquery.htm?m=QueryData&dbcode=hgnd&rowcode=zb&colcode=sj&wds=[]&dfwds=[]"
```

返回 `200` 即通。若超时，先解决服务器出网（安全组 / 出方向规则），否则 MCP 起来也查不到数。

## 二、安装 Node.js

宝塔面板 → **软件商店** → 搜索「Node.js版本管理器」→ 安装 → 打开后安装 **v20.x LTS**。

装完在 SSH 里确认路径（**版本号以你实际装到的为准，下面所有命令都要替换成这个路径**）：

```bash
ws=$(readlink -f "$(which node)"); echo "$ws"
# 实机输出：/www/server/nodejs/v20.18.3/bin/node
node -v && npm -v
```

建议把 Node 的 bin 目录写进 `~/.bashrc`，避免每次重开终端找不到命令：

```bash
echo 'export PATH=/www/server/nodejs/v20.18.3/bin:$PATH' >> ~/.bashrc && source ~/.bashrc
```

> 只要路径在 `/www/server/...` 下就没问题；如果哪天 Node 变成了 `/root/.nvm/...`，PM2 和 systemd 都会找不到它，必须先解决。

## 三、安装并首次启动 mcp-cnbs

**用本地安装，不用 `npm install -g`。** 全局安装会把包写进 `/www/server/nodejs/v20.18.3/lib/node_modules`，污染宝塔的 Node 环境；本地安装到 `/home/www/workbuddy/apps/mcp-cnbs` 后，删目录即彻底卸载，`/www/server` 下不留痕迹。

```bash
mkdir -p /home/www/workbuddy/apps/mcp-cnbs/logs
mkdir -p /home/www/workbuddy/sites
chown -R www:www /home/www/workbuddy

cd /home/www/workbuddy/apps/mcp-cnbs
npm init -y >/dev/null
npm install mcp-cnbs --omit=dev          # 零依赖、纯 JS，几秒完成，约 4.2M

# 生成令牌并落盘（学生端要用，丢了只能重新生成、全班重配）
echo "MCP_CNBS_AUTH_TOKEN=$(openssl rand -hex 24)" > service.env
chown -R www:www /home/www/workbuddy
chmod 600 service.env
cat service.env

# 前台试跑
set -a; . ./service.env; set +a
node node_modules/mcp-cnbs/dist/index.js --port 12345
```

看到这两行即为成功，按 `Ctrl+C` 停掉，改由 systemd 守护：

```
CNBS MCP HTTP server running on 127.0.0.1:12345 with authentication enabled
Authorization: Bearer <token> required
```

> **为什么用环境变量而不是 `--auth-token` 参数**：命令行参数会出现在 `ps aux` 里，服务器上任何有权限的进程都能看到令牌。环境变量不会。

## 四、用 systemd 守护（开机自启 + 崩溃重启）

**不用 PM2。** PM2 本身也要 `npm i -g`，等于又往 Node 目录里塞东西，还会多一个 `~/.pm2` 常驻守护进程；而且它依赖当前的全局 Node 路径，将来换 Node 版本容易连带失效。systemd 不装任何包，只在 `/etc/systemd/system/` 放一个 unit 文件。

```bash
cat > /etc/systemd/system/mcp-cnbs.service <<'EOF'
[Unit]
Description=CNBS MCP Server (China NBS data for WorkBuddy)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=www
Group=www
WorkingDirectory=/home/www/workbuddy/apps/mcp-cnbs
EnvironmentFile=/home/www/workbuddy/apps/mcp-cnbs/service.env
ExecStart=/www/server/nodejs/v20.18.3/bin/node /home/www/workbuddy/apps/mcp-cnbs/node_modules/mcp-cnbs/dist/index.js --port 12345 --host 127.0.0.1
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now mcp-cnbs
systemctl status mcp-cnbs --no-pager     # 应显示 active (running) 且 enabled
journalctl -u mcp-cnbs -n 15 --no-pager  # 应看到上面那两行启动日志
```

`ExecStart` 里的 Node 路径要换成你机器上 `readlink -f "$(which node)"` 的实际结果。

## 五、宝塔建站 + 反向代理 + HTTPS

### 5.1 建站

宝塔 → **网站** → 添加站点 → 填你的域名（如 `cnbs.你的域名.com`）→ 纯静态 → 不建数据库、不建 FTP。

### 5.2 申请 SSL

站点设置 → **SSL** → Let's Encrypt → 勾选域名 → 申请。

- 域名已备案且 80 端口通：直接文件验证，一键成功。
- 域名未备案或 80 被拦：改用 **DNS 验证**（同一个页面有「DNS验证」选项卡），按提示到域名商加一条 TXT 记录，等 2 分钟再点验证。

申请成功后**打开「强制 HTTPS」**。

### 5.3 配反向代理

**这一步必须先分清你的面板跑的是哪个 Web 服务器**，两者配置完全不同。网上教程九成默认 Nginx，照抄会卡在「面板里找不到反向代理按钮」：

```bash
ps -ef | grep -E 'httpd|nginx' | grep -v grep | head -3
```

- 出现 `httpd` → **Apache**，走方案 A（宝塔默认装的就是 Apache，实机即此情况）
- 出现 `nginx` → **Nginx**，走方案 B

#### 方案 A：Apache

**A-1 先确认 proxy 模块是否已加载**（多数宝塔 Apache 环境其实已经开了，别盲改）：

```bash
grep -nE '^\s*#?\s*LoadModule (proxy|proxy_http|proxy_connect|headers)_module' /www/server/apache/conf/httpd.conf
```

- 行首**没有** `#` → 已加载，跳到 A-2，`httpd.conf` 一个字都不用改
- 行首**有** `#` → 取消注释后再继续：

```bash
cp /www/server/apache/conf/httpd.conf /www/server/apache/conf/httpd.conf.bak
sed -i -E 's/^#(LoadModule (proxy|proxy_http|proxy_connect|headers)_module)/\1/' /www/server/apache/conf/httpd.conf
/www/server/apache/bin/httpd -t     # 必须 Syntax OK，否则先 cp 回来
```

**A-2 把反代配置放进 `extension` 目录（关键：别改站点 vhost）**

宝塔生成的站点配置里有一行 `IncludeOptional /www/server/panel/vhost/apache/extension/<站点>/*.conf`，这是面板留给人工附加配置的目录，**面板重写站点配置时不会覆盖它**。改站点 vhost 的风险在于：以后在面板里点一下 SSL、改一次目录，你写进去的 ProxyPass 就被抹掉了。

注意站点配置文件名会被宝塔**去掉点号**，`cnbs.lets.zone` 对应的是 `cnbslets.zone.conf`，不是 `cnbs.lets.zone.conf`。

```bash
mkdir -p /www/server/panel/vhost/apache/extension/cnbslets.zone

cat > /www/server/panel/vhost/apache/extension/cnbslets.zone/cnbs-proxy.conf <<'EOF'
# CNBS MCP 反向代理（人工维护，宝塔面板不会覆盖）
ProxyPreserveHost On
ProxyTimeout 300

# 证书续期验证路径必须排除，否则 Let's Encrypt 90 天后自动续期会静默失败
ProxyPass        /.well-known/ !

ProxyPass        / http://127.0.0.1:12345/ flushpackets=on timeout=300
ProxyPassReverse / http://127.0.0.1:12345/
EOF

/www/server/apache/bin/httpd -t          # 必须 Syntax OK
/etc/init.d/httpd reload                 # 平滑重载，不中断其他站点
```

**两个刻意留的细节，别删：**

- `flushpackets=on` —— Apache 版的 `proxy_buffering off`。不写它，Apache 会攒够一批数据才吐给客户端，MCP 的流式响应变成「连上了、一直转圈、最后超时」。这是宝塔 + Apache 部署 MCP 最典型的坑。
- `ProxyPass /.well-known/ !` —— 全量反代会把证书验证请求也转给 MCP，导致三个月后自动续期失败，而且失败是静默的，等发现时证书已经过期。

**A-3 注意**：`ProxyPass /` 会把整个站点转给 MCP，所以这个子域名必须建成**独立站点**（纯静态、没有其他页面），不要叠加到有内容的主站上。

#### 方案 B：Nginx

站点设置 → **反向代理** → 添加反向代理：

| 字段 | 值 |
|---|---|
| 代理名称 | cnbs |
| 目标 URL | `http://127.0.0.1:12345` |
| 发送域名 | `$host` |

提交后，**必须手动改配置文件**——这一步是整个部署最容易出问题的地方。

点该反代右侧「配置文件」，把内容替换成下面这份（域名和证书路径换成你自己的）：

```nginx
location / {
    proxy_pass http://127.0.0.1:12345;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_request_buffering off;

    proxy_connect_timeout 30s;
    proxy_send_timeout 300s;
    proxy_read_timeout 300s;

    chunked_transfer_encoding on;
}

location /mcp {
    proxy_pass http://127.0.0.1:12345/mcp;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection "";

    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
}
```

**`proxy_buffering off` 不能省。** Nginx 默认开启缓冲，会等后端把响应全写完才吐给客户端；而 MCP 走的是流式响应（SSE），一旦缓冲，客户端会一直等到超时，表现为「连上了但一直转圈、不出结果」。这是宝塔部署 MCP 最常见的问题。

### 5.4 防火墙（两层都要放行，少一层都连不上）

**第一层：服务器 ufw**（实机已启用，默认拒绝入站）：

```bash
ufw allow 80/tcp
ufw allow 443/tcp
ufw status numbered
```

**第二层：阿里云安全组**。控制台 → 实例 → 安全组 → 入方向，同样放行 80、443。

**`12345` 端口不要放行**，让它只听 `127.0.0.1`。宝塔面板的「安全」页也顺手核对一遍。

### 5.5 应急：没有域名，直接开端口

来不及配证书时的兜底方案（**令牌会明文传输，只建议开课前临时用，课后立即轮换**）：

```bash
# 1) PM2 启动参数从 --port 12345 改成 --host 0.0.0.0 --port 12345
# 2) 放行端口（ufw + 安全组都要）
ufw allow 12345/tcp
```

安全组「来源」填学生所在网段，**不要填 `0.0.0.0/0`**。客户端地址填 `http://服务器公网IP:12345/mcp`。

## 六、验证（10 分钟自测清单）

### 6.1 服务在跑

```bash
pm2 status
# 注意：必须用 POST 探测，GET /mcp 不带 session 会返回 400/405，那是正常现象别当故障
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:12345/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"t","version":"1"}}}'
```

- 返回 `401` → 进程正常且**鉴权已生效**（这是期望结果）
- 返回 `200` → 进程正常但**没设令牌**，危险，回第三节检查环境变量
- 返回 `000` / 连接被拒 → 进程没起来，看 `pm2 logs mcp-cnbs`

### 6.2 外网能通、令牌生效

```bash
curl -s -X POST "https://cnbs.你的域名.com/mcp" \
  -H "Authorization: Bearer 你的令牌" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"test","version":"1.0"}}}'
```

- 返回一段含 `result`、`serverInfo` 的 JSON 或 SSE 文本 → **通了**
- 返回 `401` → 令牌不对或没带
- 返回 `502` → 反代指向错，检查 127.0.0.1:12345
- 返回 `504` → 超时：Nginx 少了 `proxy_buffering off`，Apache 少了 `flushpackets=on`

### 6.3 工具列表正常

```bash
curl -s -X POST "https://cnbs.你的域名.com/mcp" \
  -H "Authorization: Bearer 你的令牌" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'
```

应能看到 `cnbs_search`、`cnbs_fetch_series`、`cnbs_compare`、`cnbs_economic_snapshot` 等 20 多个工具。看不到工具列表，后面学生端一定连不上。

### 6.4 真实取数（最关键的一步）

在 WorkBuddy 里添加这个 MCP（自定义连接器，填 URL 和 Bearer 令牌），然后提问：

> 用 cnbs_economic_snapshot 查一下最近一期中国 GDP、CPI、PMI 三个指标，给出数值和统计期。

能返回真实数字且带统计期 → 全线贯通。

**再查一次同样的指标**，观察响应速度是否明显变快（缓存命中）。两次耗时差不多，说明缓存没起作用，41 人同时用会有风险。

## 七、学生端接入

### 7.1 学生要做的（1 分钟）

1. 打开 WorkBuddy → 左侧「专家 · 技能 · 连接器」 → 自定义连接器
2. 填名称 `国家统计局`，URL 填 `https://cnbs.lets.zone/mcp`
3. 请求头加 `Authorization` = `Bearer 服务端 service.env 里那串 48 位令牌`
4. 点「信任」启用
5. 发一句「用国家统计局数据查 2024 年 GDP」验证

对应的连接器配置（等价写法，可发给学生照抄）：

```json
{
  "mcpServers": {
    "cnbs": {
      "type": "streamable-http",
      "url": "https://cnbs.lets.zone/mcp",
      "headers": { "Authorization": "Bearer <48位令牌>" }
    }
  }
}
```

### 7.2 教师要注意的

- **令牌全班共用一个就够**。这是公开数据，没有敏感性，防的是外部滥用而非内部泄露。
- **但令牌不能发群里公开贴**。建议课上口述或写黑板，课后更换一次。
- **41 人不要课上现配**。41 分钟全耗在配置上，课就废了。必须课前完成，配一张图文操作卡（A4，6 张界面截图），学生照着点。
- **云电脑是还原盘的话，每次开课都要重配**。这一条务必先确认，否则每节课前你得重走 41 遍。

## 八、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 连上后一直转圈不出结果 | 缓冲没关：Nginx 缺 `proxy_buffering off` ／ Apache 缺 `flushpackets=on` | 按 5.3 对应方案改，重载 Web 服务 |
| 面板里找不到「反向代理」入口 | 装的是 Apache 不是 Nginx | 走 5.3 方案 A，手改 vhost |
| `httpd -t` 报 `Invalid command 'ProxyPass'` | proxy 模块没加载 | 回 5.3 A-1 取消注释后重启 httpd |
| 改完 httpd.conf 后所有站点 502 | `httpd -t` 没过就重启了 | 恢复 httpd.conf 备份，先 `httpd -t` 验证 |
| 401 Unauthorized | 令牌错、没带 Bearer、或环境变量没生效 | `systemctl restart mcp-cnbs` 后重试 |
| 502 Bad Gateway | 反代目标错，或进程没起 | `systemctl status mcp-cnbs`、`journalctl -u mcp-cnbs -n 50` |
| 504 Gateway Timeout | 上游统计局慢 + 缓冲 | 关缓冲 + 把超时提到 300s |
| 工具列表为空 | 客户端没完成 initialize 握手 | 重启客户端，先删再加一次 |
| 查询返回空数据 | 统计局限流、指标名不匹配 | 换指标名；间隔一段时间再试；查日志有无 403 |
| 越用越慢 | 缓存未命中率高 | 查 `cnbs_get_cache_stats`；课堂尽量统一指标，提高重合度 |
| 证书 90 天后过期 | 反代把 `/.well-known/` 也代理走了 | 回 5.3 A-2 补 `ProxyPass /.well-known/ !`；宝塔 → SSL 开「自动续签」 |

## 九、运维要点

| 项目 | 建议 |
|---|---|
| 服务启停 | `systemctl start/stop/restart mcp-cnbs` |
| 开机自启 | `systemctl enable mcp-cnbs`（已配好，一般不折腾） |
| 查看状态 | `systemctl status mcp-cnbs --no-pager` |
| 日志查看 | `journalctl -u mcp-cnbs -n 100 --no-pager`（跟随：`-f`） |
| 升级版本 | `cd /home/www/workbuddy/apps/mcp-cnbs && npm install mcp-cnbs@latest --omit=dev && systemctl restart mcp-cnbs` |
| 令牌轮换 | 改 `service.env` 里的值 → `systemctl restart mcp-cnbs` → 通知学生改连接器 |
| 目录结构 | 全部集中在 `/home/www/workbuddy/`，删除该目录即彻底卸载（记得先 `systemctl disable --now mcp-cnbs`） |
| 磁盘 | journald 日志有自动上限，无需手工清理 |
| 监控 | 宝塔「监控」看 CPU 和内存；正常应常驻 20MB 级，长期低于 20% CPU |

**容量参考**：41 人一次课约 200 次请求，去重后仅 30–40 个不同请求真正落到统计局。1 核 1G 完全够用，瓶颈永远在统计局的限流，不在你的服务器。

## 附录 B：上游接口改版补丁（2026-11-01 已打，必读）

### B.1 为什么必须打这个补丁

统计局在 2025 年后改版了数据接口，而 npm 上的 `mcp-cnbs` 最新版仍是 **1.3.2**，未跟进。表现是 `cnbs_fetch_series` 一律返回 `404`，只能查到最近一两年，取不到历史序列。

| 项 | 包内旧写法（已失效） | 改版后必须的写法 |
|---|---|---|
| 取数接口 | `POST /getEsDataByCidAndDt` | `POST /stream/esData` |
| 地区字段 | `das:[{text, code}]` | `das:[{text, value}]` |
| 必填字段 | 无 | 新增 `daCatalogId:""` |

补丁脚本：`05_技术支撑/patch-mcp-cnbs-1.3.2.sh`，或手工执行：

```bash
python3 - <<'PY'
import shutil,datetime
p="/home/www/workbuddy/apps/mcp-cnbs/node_modules/mcp-cnbs/dist/index.js"
s=open(p,encoding="utf-8").read()
c1=s.count("/getEsDataByCidAndDt"); s=s.replace("/getEsDataByCidAndDt","/stream/esData")
old='das:e.areas||[{text:"\\u5168\\u56FD",code:"000000000000"}],dts:e.periods'
new='daCatalogId:"",das:(e.areas&&e.areas.length?e.areas:[{text:"\\u5168\\u56FD",code:"000000000000"}]).map(function(a){return{text:a.text||"\\u5168\\u56FD",value:a.value||a.code||"000000000000"}}),dts:e.periods'
c2=s.count(old); s=s.replace(old,new)
print("路径 %d 处 / 请求体 %d 处"%(c1,c2))
assert c1 and c2, "版本不匹配，未修改"
shutil.copy2(p,p+".bak-"+datetime.datetime.now().strftime("%Y%m%d%H%M%S"))
open(p,"w",encoding="utf-8").write(s); print("已备份并写入")
PY
node --check /home/www/workbuddy/apps/mcp-cnbs/node_modules/mcp-cnbs/dist/index.js && systemctl restart mcp-cnbs
```

期望输出：`路径 3 处 / 请求体 1 处` → `已备份并写入` → 无报错（`node --check` 通过时静默）→ 服务重启。

**回滚**：把 `index.js.bak-<时间戳>` 改回 `index.js`，`systemctl restart mcp-cnbs`。
**切勿 `npm install mcp-cnbs@latest`**——会覆盖补丁。升级前先确认新版本是否已修此问题。

### B.2 验收（正确写法）

```bash
# 数数据点个数，不要用 grep '"YY"'——SSE 里内层 JSON 被转义成 \"2015YY\"，匹配不上
curl -s --max-time 90 -X POST https://cnbs.lets.zone/mcp \
  -H "Authorization: Bearer $TOKEN" -H "Mcp-Session-Id: $SID" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"cnbs_fetch_series","arguments":{"setId":"f7fd25aaad184414875632cf2327da60","metricIds":["7dc6a2ee6c614960b7059991e0cc4d96"],"periods":["2015YY-2024YY"]}}}' \
  | grep -o '"code"' | wc -l
```

返回 **10** 即为修复。或直接看内容里是否出现 `2015YY`、`2024YY` 与具体数值。

### B.3 工具可靠性清单（2026-11-01 实测，务必按此出题）

| 工具 | 状态 | 说明 |
|---|---|---|
| `cnbs_fetch_series` | ✅ 打完补丁可用 | 唯一能取多年序列的工具，课堂趋势题必须用它 |
| `cnbs_search` | ✅ 可用 | 返回最新期值 + `cid`/`indic_id`，是取序列的前置步骤 |
| `cnbs_batch_search` | ✅ 可用 | 多关键词批量搜索 |
| `cnbs_fetch_nodes` / `cnbs_fetch_end_nodes` | ✅ 可用 | 分类树下钻 |
| `cnbs_fetch_metrics` | ✅ 可用 | 列数据集内指标 |
| `cnbs_economic_snapshot` | ❌ 不可用 | 10 项全 `null`。根因：`batchFindItems` 返回嵌套结构，取第一条时逻辑写错，永远取不到。**不要修**——修好后取的是"搜索结果第一条"，会把 GDP 显示成"贡献率 100%"、PMI 显示成"电子商务采购额"，比 null 更误导 |
| `cnbs_compare` | ⚠️ 部分可用 | `compareType:"region"` 可用；`compareType:"time"` 只会返回最新一年，因为它只对搜索结果做过滤，不调取数接口。历史对比改用 `cnbs_fetch_series` |
| `ext_world_bank` 等国际源 | ✅ 可用 | 历史序列完整，可作为跨国/长周期题的数据源 |

**课堂出题原则**：趋势/多年对比题 → 明确要求用 `cnbs_fetch_series`；一次看多项指标 → 拆成多次 `cnbs_search` 或 `cnbs_fetch_series`，**不要用 `cnbs_economic_snapshot`**。

### B.4 标准取数三步（模型自己会走，但要知道原理）

```
① cnbs_search(keyword, categories=["3"])        → 拿到 cid(setId) 和 indic_id(metricId)
② cnbs_fetch_series(setId=cid, metricIds=[indic_id], periods=["2015YY-2024YY"])
③ 检查返回的 data 数组长度是否等于预期年数
```

`periods` 格式是 `<年>YY`，区间用 `-` 连接；月度是 `YYYYMM01-YYYYMM12` 这类写法。

### B.5 一个必须提前准备的答疑

2023 年 GDP 在统计局口径是 **1,294,271.7 亿元**，而不少教材写 **1,260,582 亿元**（初步核算数）。差额来自第五次全国经济普查后的修订。学生一定会问，答案就是"同一个指标，初步核算数与修订数都对，差在普查修订"。

### C.2 严重风险：统计局对同一 IP 限流

**实测经过**：连续调用约 30 次 `cnbs_*` 工具（几分钟内）后，所有 `cnbs_*` 工具开始返回
`Maximum number of redirects exceeded`，而 `ext_world_bank` 仍正常。同一时刻从另一台机器（不同公网 IP）直连
`data.stats.gov.cn` 返回 `200`。

**结论**：不是服务坏了，是**统计局对服务器 IP 做了频率限制/临时拦截**。上游返回 302 循环，axios 跟随后报错。

**对课堂的直接影响**：41 人同时提问，如果题目各不相同，命中缓存率极低，几分钟内就能把服务器 IP 打进限流状态，**全班同时失效**，而且你在服务端看不出原因（日志里只有 redirect 错误）。

**三条必须做的缓解措施：**

1. **统一题目**。`cnbs_search` 缓存 24 小时、`cnbs_fetch_series` 缓存 1 小时，同一个问题第二个人问就是缓存命中，不打上游。老师课前先用这几道题各跑一遍预热。
2. **课上把题量压到 3–5 道**，全班共用，不要每人一题。
3. **准备国际源兜底**。`ext_world_bank` / `ext_imf` / `ext_oecd` 不受统计局限流影响，可以随时切过去继续上课。

**临时恢复办法**：等（通常几十分钟到数小时自动解除），或换出口 IP。不要反复重试——每次重试都在延长封禁。

**判断方法（一条命令）：**

```bash
# 在服务器上跑，200 = 已恢复；302 或报错 = 仍在限流
curl -s -o /dev/null -w '%{http_code}\n' --max-time 20 \
  "https://data.stats.gov.cn/dg/website/publicrelease/web/external/new/queryIndexTreeAsync?code=3" \
  -H 'User-Agent: Mozilla/5.0 Chrome/120' -H 'Referer: https://data.stats.gov.cn/dg/website/page.html'
```

### C.3 修正后的四道课堂题（可直接发）

**①（保留）**
> 用 cnbs_fetch_series 取 2015–2024 年中国 GDP 年度数据，先 cnbs_search(keyword="国内生产总值", categories=["3"]) 拿 setId 和 metricIds。列成表格，标注统计期和单位。

**②（替换掉 snapshot）**
> 用 cnbs_search 分别查「居民消费价格指数」「工业生产者出厂价格指数」的年度口径最新值，给出数值、单位、统计期。不要用 cnbs_economic_snapshot。

**③（省级取不到，改成国际多国对比）**
> 用 ext_world_bank 对比中国、美国、日本、德国 2020–2024 年 GDP 增速，做成表格，并说明 2020 年各国差异的原因。

**④（保留）**
> 用 ext_world_bank 对比中国和美国 2020–2024 年的 GDP 增速，并说明世行增速口径与统计局「比上年增长」口径的差异。

### C.4 口径差异（④ 的标准答案要点）

- **世行**：按不变价 GDP 计算的年增长率，用美元折算不影响增速，但对基年选择敏感
- **统计局**：「比上年增长」按不变价计算，与世行同源但基期与修订时点不同
- 中美 2020 年反差（2.34% vs -2.08%）是疫情冲击 + 统计口径 + 防控政策差异的综合结果，讲课时不要只归因于单一因素

1. **交叉校验点**：「就业人员」同时在「按三次产业分」和「按城乡分」两个数据集里，两次独立取数结果必须一致（2025 年都是 72504）。让学生做完这一步自检，能筛掉大部分取数错误。

### D.2 客户端怎么知道该调哪个工具（不需要发手册）

MCP 的调用知识不在任何本地文件里，来自三层：

| 层 | 来源 | 学生要做什么 |
|---|---|---|
| ① 协议层 | 客户端连接时发 `tools/list`，服务器返回 **31 个工具的 name + 中文描述 + 完整参数 schema**，原样注入模型上下文 | 什么都不用做，连上就懂 |
| ② 服务器内置指南 | 工具 `cnbs_get_guide`，返回 **5387 字**说明：十大场景、分类代码、时间格式、地区代码、世行/IMF 指标速查 | 问一句「你能做什么」即可触发 |
| ③ 提问质量 | 学生自己的 prompt | **唯一需要教的部分** |

所以换电脑、重装客户端、换账号，只要 JSON 里的 url 和令牌正确，能力自动跟着走——因为说明是服务器发出来的。

**但内置指南有两处与实际不符，必须人工纠偏：**

- 指南称「`cnbs_fetch_series` 的 value 可能为空」，那是**打补丁前**的状态，现已修复；
- 工具描述称 `cnbs_fetch_nodes` 用 `isEnd` 判断叶子节点，实际返回字段是 **`_id` 和 `isLeaf`**。

**给学生的一句话开场白（贴在对话开头，或写进项目记忆）：**

```
用 cnbs 取数时：cnbs_search 返回的每一条里，cid 就是 setId，indic_id 就是 metricId，
把这两个喂给 cnbs_fetch_series；年度 periods 写 2016YY-2025YY，月度写 201601MM-202512MM。
categories 过滤不生效，会混入无关指标，定位不到就把 pageSize 调到 200。
取不到数据就直说，不许估算或编造数值。
```

最后一句不能省：上游取不到时，模型会倾向于"估一个像样的数"。

### D.3 限流的第二次实证

按分类树逐层找「城镇调查失业率」节点，约 **20 余次** `cnbs_fetch_nodes` 后，一批请求同时报 `Maximum number of redirects exceeded`——比附录 C.2 记录的"约 30 次"更早触发。

**结论：BFS 遍历分类树是最快打死 IP 的操作。** 因此课堂题必须**指定指标名 + 指定年份区间**，让 AI 一步 `cnbs_search → cnbs_fetch_series` 命中，禁止"你帮我找找失业率在哪"这类开放式问法。

### D.4 一处需更正的说法

附录 B.4 与先前口头说明中提到的"`cnbs_search` 不返回 setId"**不准确**：它返回的 `cid` 字段就是 setId，`indic_id` 就是 metricId。真正的问题是**分页**（`count` 可能是 488 而单页只给 8 条）和**`categories` 过滤失效**（传 `["月度数据"]` 仍返回年度数据）。定位指标时把 `pageSize` 调大即可，无需遍历分类树。
